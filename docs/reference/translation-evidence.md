# Translation evidence and terminology checks

In **Setup**, select a glossary and save the profile. Expand **Test assets**, choose language names, and enter source text. The test uses the production matcher without calling a model. A match shows the expected target form; it does not mean a model received or followed that term.

In **Translation Records**, search source or target text or a request ID, then open a record. Source and target appear first. Each segment records the profile, model, asset identity/fingerprint, matched entries, whether a successful model request used them, and the terminology check. No match, disabled glossary, unavailable language pair, asset failure and missing historical evidence are distinct from a passed check. A passed terminology check does not evaluate overall translation quality. Cached results are checked with current terms; the cache's original generation evidence is not available.

**Translate again with current profile** uses current saved settings and asset contents, bypasses translation and local prompt-response caches, and may incur model charges. It creates a linked record and displays an old/new comparison. It never writes into the memoQ editor. Select another saved profile if the original one was deleted. Closing the panel does not cancel a request already sent to a provider; its record remains in History.

Terminology policy defaults to **Return translation with warnings**. **Reject terminology violations** withholds a noncompliant segment. **Allow one terminology repair attempt** is separately opt-in and permits one more model call per failing segment. A repair must pass both terminology and tag/placeholder checks. Batch partial results keep successful segments; the updated plugin does not retry policy-rejected segments in different formatting modes. Install the updated plugin alongside Hub to retain this retry boundary.

The memoQ MT SDK does not expose a custom editor toolbar or editor writeback command. The supported entry is the plugin **Options** window: copy the **Hub record** ID from result information, paste it into **Hub record ID**, and click **View translation record in Hub**. Start the updated Hub once to register its Windows protocol. If a portable folder moves, start Hub at its new location before using the shortcut. Missing/expired or duplicate IDs never select a similar record; search History manually when necessary.

Protocol implementation follows the [Electron deep-link guide](https://www.electronjs.org/docs/latest/tutorial/launch-app-from-url-in-another-app). Wire additions are specified in [the shared result-evidence contract](../../packages/contracts/translation-result-evidence.md). Existing settings and history are preserved. Rollback uses the previous published installer/portable archive; back up the local app-data directory before changing versions. Never delete records as a rollback step.
