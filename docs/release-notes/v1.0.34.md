## Highlights

- Local database commits now write and sync a validated temporary image before atomically replacing the primary database.
- The previous valid database generation is retained as a recovery backup; startup validates the primary with SQLite `quick_check` and restores the backup when required.
- Standalone and worker-local runtime modes no longer create reversible Base64 credential files. Provider credential writes outside the Electron secure-storage bridge fail closed with `OS_SECRET_STORAGE_UNAVAILABLE`.
- Malformed JSON and request bodies over 10 MB now return the gateway's stable JSON error contract with `INVALID_JSON` or `REQUEST_BODY_TOO_LARGE`.
- The desktop runtime benchmark now injects the same explicit secret-adapter boundary as the production worker, reports that composition in schema version 2, and no longer measures the removed legacy `electron-store` path.
- Removed the unused `electron-store` production dependency and excluded the legacy secret module from release packages.

## Compatibility

- No IPC, HTTP route, database schema, plugin protocol, Profile, QA, history, or update-manifest format changed.
- Existing valid databases open normally. A new `.bak` sibling is created only after a later successful database generation is committed.
- Existing legacy Provider credentials continue to migrate only through the Windows `safeStorage` main-process service introduced in v1.0.33.

## Verification

- Focused database recovery, secret bridge, gateway error, runtime, QA history, benchmark-contract, and package-content tests passed.
- Desktop regression passed 574 tests with 4 packaging-only conditional skips; the final packaged bundle passed all 4 package-state checks.
- Repository governance, renderer production build, Ant Design scan, plugin build/regression, and Windows release packaging passed.
- Seven isolated production-composition samples measured a 146.36 ms median runtime startup, 63 loaded modules, and a 25.1 MiB median RSS increase.

## Rollback watchpoints

- Roll back to `v1.0.33` if an existing valid local database cannot open, writes fail repeatedly, or startup recovery selects the wrong generation.
- Preserve `memoq-ai-hub.db` and `memoq-ai-hub.db.bak` together when collecting diagnostics; do not delete either file as a recovery shortcut.
- A rollback restores the removed standalone reversible-secret path. Do not use that path to work around unavailable Windows secure storage.
