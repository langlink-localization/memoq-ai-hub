## Language-aware terminology assets

- New glossary imports match ordinary terms to the translation request's language direction. Bilingual and multilingual tables use the same language-column model without requiring a fixed source and target language for the asset.
- Table previews show one concept per row with its corresponding terms in each language, instead of expanding concepts into source/target pairs.
- Ordinary terms remain reusable in both directions. Missing cells do not create substitute translations.

## Directional rules and evidence

- Forbidden terms, allowed variants, and other effective directional rules only apply to their specified language direction. Rule-bearing rows are not reversed or reused for other language pairs.
- Language-column tables require a rule direction when effective rules are present. Unconfigured rule-bearing rows are excluded from matching, with clear guidance in the preview and translation evidence.
- Empty rules, false flags, zero priority, and default phrase matching do not restrict ordinary terminology.
- Translation records show the matched language direction and identify directional rules. Missing rule configuration is distinguished from a valid asset with no matching terms.

## Compatibility and delivery

- Existing assets keep their previous matching behavior. Editable tables can opt into automatic language matching from the asset preview; existing records remain unchanged.
- The legacy source/target mapping API remains supported. The memoQ plugin contract and database schema are unchanged; no settings migration is required.
- Windows portable ZIP, compact 7z, Squirrel setup EXE, and the stable update manifest are published by the repository release workflow.
