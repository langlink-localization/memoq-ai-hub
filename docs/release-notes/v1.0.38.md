## Highlights

- The renderer app shell was decomposed without behavior change: App.jsx went from 2,345 to 923 lines as log diagnostics, dashboard install/update flows, history filters, the asset preview drawer, provider management, profile management, and the navigation chrome each moved into focused hooks and components with explicit dependencies.
- The renderer IPC surface is now generated from a single table (`rendererIpcSurface.js`) shared by `preload.js` and the main-process registrar, replacing the previous hand-maintained parallel registrations in three files; the bridge remains exactly 60 methods and is guarded by a surface test.
- The runtime gained explicit-dependency services for history presentation (`runtimeHistoryPresentation.js`) and the renderer-facing app-state read model (`runtimeStateView.js`), continuing the composition-root decomposition.
- Renderer logic modules stay single-sourced: a repository-layout guard fails when a `.js`/`.mjs` twin reappears, and the root package version cannot drift from the desktop package version.

## Compatibility

- No IPC channel, bridge method, HTTP route, database schema, plugin protocol, Provider, Profile, asset, QA, history, or update-manifest behavior changed. The database schema version stays at 1.
- Page behavior, navigation guards, pending-operation tracking, and keyboard/aria contracts are preserved; the extraction moved code without altering JSX structure or class names.
- No plugin-side change is required relative to v1.0.37.
