## Update center

- Installed builds can now update entirely in-app: the stable manifest publishes the Squirrel Windows installer (`memoq-ai-hub-setup.exe`) with a SHA-256 digest, and the release workflow uploads it beside the portable archives. The dashboard downloads the installer, verifies it against the manifest digest, and relaunches the verified installer after a restart confirmation.
- Portable builds can update in-app instead of downloading and overwriting manually. The dashboard downloads the verified ZIP, re-verifies it before extraction, stages it beside the app (or under user data when that location is not writable), and swaps the app folder during a restart orchestrated by a detached apply helper. The helper waits for the app to exit, retries the folder rename while file locks drain, rolls the rename back if the move fails, and relaunches the previous version on failure.
- The browser download page remains available as a fallback for portable installs whose app folder is not writable.
- Update downloads now stream to disk instead of buffering in memory, verify the SHA-256 digest incrementally, and report byte-level progress on the dashboard.
- Restart-to-update is blocked while AI requests are active, and an interrupted apply session is detected on the next start so a staged update can be retried.

## Reliability and architecture

- Application-managed downloads fail closed at every boundary: digest verification before the file is renamed into place, re-verification before extraction, staging validation before the apply helper is scheduled, and digest re-verification immediately before the installer is launched.
- Startup removes stale apply backups while preserving staged updates that may still be applied after an interrupted session.
- User data (profiles, providers, history, secrets, logs) is untouched by updates; no database migration or memoQ plugin protocol change is required.

## Compatibility and delivery

- Windows portable ZIP, compact 7z, Squirrel setup EXE, and the stable update manifest are produced and published by the repository release workflow.
- The unsigned installer may raise a Windows SmartScreen prompt; the release notes and user guide describe confirming it.
- Existing update-state files from earlier versions are normalized on first launch; portable builds that previously only opened the download page gain the in-app flow after updating once.
