## Terminology and import

- A single terminology table can contain multiple language columns and serve different translation pairs, including reverse translation, without importing the file again.
- Column languages can be selected by name with sample values shown alongside them. Files without headers retain the first row of terms.
- Terminology matching keeps explicitly different scripts and regions separate. Empty cells do not pair terms across rows, and imports report an error when multilingual expansion exceeds 50,000 entries.
- Previews show samples from different language pairs. Quoted fields containing commas, tabs, or line breaks are read correctly.

## Asset management

- Terminology and translation memory imports have direct entry points with file-type filters.
- The asset list shows configured languages and supports searching by file, language, or translation profile, with filters for assigned and unassigned assets.
- Assets can be renamed and assigned to or removed from translation profiles in one dialog. Pending replacements are shown before saving, and concurrent edits are protected from being overwritten.
- Disabled features can be explicitly enabled when assigning an asset. Unsaved changes are protected.
- Assets must be removed from their profiles before deletion. Deleting an asset removes the imported copy and preserves the original source file.

## Compatibility and delivery

- Existing bilingual asset settings remain supported. The memoQ plugin contract and the database schema are unchanged. No settings migration is required.
- Windows portable ZIP, compact 7z, Squirrel setup EXE, and the stable update manifest are published by the repository release workflow.
- Automated regression and asset persistence checks passed. Interactive acceptance in a live Windows/memoQ session has not been completed.
