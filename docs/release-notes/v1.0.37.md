## Highlights

- The memoQ plugin now verifies the desktop gateway's contract version through `GET /desktop/version` before its first request, so mismatched plugin/desktop installs fail fast with an actionable message instead of opaque per-segment errors. `store-translations` requests now also carry the contract version.
- The local gateway now shape-validates POST payloads before they reach runtime services. Non-object bodies and missing required MT fields (segments, language pair, `jobRequestId`, `translations`) return a typed `REQUEST_PAYLOAD_INVALID` error with status 400.
- The local database gained versioned schema migrations: `PRAGMA user_version` tracks the applied schema version, a migration list replaces the ad-hoc column patching, fresh databases are stamped at creation, and databases from a newer app version are rejected with `SCHEMA_VERSION_TOO_NEW` instead of being opened with a mismatched shape.
- Renderer logic modules are single-sourced: the duplicate `.js` test copies of `providerConnectionUx` and `providerDraftDefaults` were removed, tests import the `.mjs` sources directly, and a repository-layout guard prevents `.js`/`.mjs` twins from returning.
- Placeholder app-state slices (preview status, update center) collapsed into one shared builder used by both the main-process startup placeholder and the renderer fallback; the previously drifted `portableDownloadUrl` placeholder field is now consistent.
- Silent empty `catch` blocks were reviewed: the unreadable secret-store case now logs a warning, and best-effort cleanup paths carry an explanatory comment.

## Compatibility

- The gateway contract version stays at `1`. The plugin's handshake failure on mismatch is the only new visible behavior; identical plugin and desktop versions behave exactly as before.
- `store-translations` without a `contractVersion` remains accepted for backward compatibility; a present but mismatched version is rejected with 409.
- Existing local databases open normally: the baseline migration re-applies the existing history columns idempotently and stamps version 1. No data is rewritten.
- No UI flow, IPC channel, Provider, Profile, asset, QA, history, or update-manifest behavior changed.

## Rollback watchpoints

- Roll back to `v1.0.36` if the plugin's contract handshake wrongly rejects a matching desktop install, or if gateway payload validation rejects a legitimate memoQ request shape.
- Databases stamped with schema version 1 must not be opened by v1.0.36 or older builds that would ignore the version marker; restore the previous database file pair (`memoq-ai-hub.db` and `memoq-ai-hub.db.bak`) together when rolling back.
- A mismatched plugin/desktop pair should be resolved by updating both to matching versions, not by bypassing the handshake.
