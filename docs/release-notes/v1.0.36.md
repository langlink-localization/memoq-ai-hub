## Highlights

- Added a complete **Project Rules** page for routing memoQ project metadata to saved translation Profiles.
- Added complete rule operations: create, edit, copy, enable, disable, delete, inspect hit counts, and test matches without starting a translation.
- Added rule conditions for client, domain, subject, project, source and target language, document regular expression, and segment status. Non-empty conditions within a rule use AND semantics.
- Added clear handling for catch-all rules, duplicate priorities, invalid regular expressions, missing Profiles, default-Profile fallback, and explicit plugin Profile overrides.
- Fixed source/target language normalization in the interactive rule tester and preserved server-owned hit counts when a rule is edited or toggled.

## Compatibility

- No IPC, HTTP route, database schema, plugin protocol, Provider, Profile, history, asset, QA, or update-manifest contract changed.
- Existing persisted mapping rules become visible and manageable without migration. Equal-priority rules retain their existing saved order.
- A non-empty **Default Profile ID** in memoQ plugin settings remains authoritative and overrides Project Rules for that plugin configuration.
- memoQ 12 live-host validation remains pending. This release does not claim that the new page has been exercised inside a real memoQ host.

## Rollback watchpoints

- Roll back to `v1.0.35` if rule ordering, rule toggles, Profile deletion guards, metadata normalization, default-Profile fallback, or existing translation routing regresses.
- If a saved rule references a deleted or otherwise unavailable Profile, repair or remove that rule; do not silently route it to a different non-default Profile.
- Do not weaken the plugin's explicit **Default Profile ID** override to make Project Rules appear to win. The explicit plugin setting remains the compatibility boundary.
