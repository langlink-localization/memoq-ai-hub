## Fixes

- Fixed provider API key saves incorrectly reporting that Windows secure credential storage is unavailable. Encryption readiness is now checked when credentials are used, including after Electron finishes starting.
- Deferred legacy credential migration until Windows encryption is available and retained retry behavior after a temporary failure. Credentials continue to require OS encryption.
- Restored dashboard messages for preview bridge status and prepared updates that were lost during the v1.0.38 runtime extraction.

## Security and regression protection

- Updated the transitive development dependency js-yaml to 4.3.2 to address GHSA-2883-xcg3-v3hh.
- Extended undefined-variable lint checks to the main process, runtime, tests, and tooling.
- Added credential readiness, migration recovery, and dashboard notice regression tests. Reviewed changes from v1.0.37 through v1.0.43 across renderer, IPC, runtime, typed modules, dependencies, and packaging.

## Compatibility

- No database schema or memoQ plugin protocol changes are required.
- Close the previous app and extract the new portable package into a new directory. Keep existing user data and configuration, then save the provider API key again if its previous save failed.
